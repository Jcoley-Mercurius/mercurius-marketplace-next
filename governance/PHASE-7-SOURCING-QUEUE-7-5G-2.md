### 2.1 The reader

`STABLE`, `SECURITY DEFINER`, `search_path = ''`, guarded by `private.require_admin()` (`42501`). Execute revoked from `public`, `anon`, `authenticated` and `service_role`, then granted to `authenticated` only.

- **Entry (E-1):** `status = 'pending'` and `matching_status in ('exhausted', 'awaiting_consent', 'sourcing')`. `needs_admin_review` is not read (SG-1).
- **Kind:** `exhausted`, `awaiting_consent`, `legacy_sourcing`; never merged or relabeled (SG-5, SG-8).
- **Related event (SG-2):** `provider_operation` = latest `job_operations.created_at` with kind `provider_cancel` or `no_show`; `offer_closed` = latest `greatest(declined_at, withdrawn_at, responded_at)` over attempts with outcome `declined`, `expired` or `withdrawn`; the later of the two, `provider_operation` on equal times; `request_created` = `service_requests.created_at` when neither exists. `updated_at` and `expires_at` are not read.
- **`plan_visit`:** `recurrence_parent_id is not null` (SG-6).
- **`offer_terms_block`:** `exhausted` and the latest `offer_terms_blocks` row has no `offer_terms_retries` row strictly later: the condition `admin_offer_terms_queue` uses for `blocked_inactive` (SG-3). `candidates` is not read.
- **Order:** `related_event_at`, then `request_id`. **Shape:** `{checked_at, items: [{request_id, kind, related_event_at, related_event, plan_visit, offer_terms_block}]}`.

### 2.3 The page

`/admin/sourcing`: heading "Sourcing" and the approved description; "Checked …"; a count heading; "Listed by latest related event, earliest first. The time is the stored event named beside it."; "This page only reads. It makes no offer, assignment or other change, and it does not settle expired offers."; per item the request id, the kind label, "Latest related event" as "<event label> · <Eastern time>", and the markers "Plan visit: plan's provider only" and "Also in Offers at other terms". Empty: "No requests in this queue." Error: the server message with its code. `42501`: "Admin access required" / "This account can’t read the sourcing queue." The only control is Refresh. No link inside the page.

### 2.4 Account-bound reads

`SourcingQueueController` (as 7.5E F-1 and 7.5F-2): every read records the owner's epoch and a sequence number. A different owner, sign-out (`null`) or unmount starts a new epoch and resets the state, so an answer, a refusal or an error that arrives for an earlier epoch, or for a superseded refresh, is discarded. The hook shows a blank state until the controller has switched, and the page remounts per account (`key={user.id}`).
